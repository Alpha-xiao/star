## BabyStar 家庭协作模块 — 架构设计

> 本文档定义了 BabyStar 的多用户协作带娃能力，覆盖数据模型、邀请机制、权限体系、后端 API、前端状态管理和页面设计。
> 前置依赖：鉴权模块（`plan/鉴权模块架构设计.md`）必须先完成。

---

### 一、场景与问题定义

#### 1.1 目标场景

中国家庭的典型带娃配置：爸爸、妈妈、爷爷、奶奶、外公、外婆、月嫂/保姆。这些人需要在**同一个宝宝**的数据上协作——妈妈喂了奶记一条，奶奶换了尿布记一条，月嫂半夜喂奶也记一条。所有人打开 App 看到的是同一份记录。

#### 1.2 当前问题

鉴权模块完成后，每个用户只能看到和操作自己创建的宝宝（`Baby.ownerId === request.user.userId`）。这意味着：
- 爸爸和妈妈各自注册账号后，看到的是两份完全隔离的数据
- 没有机制让爸爸"加入"妈妈的宝宝
- 爷爷不会注册账号——他需要一个极简的加入方式

#### 1.3 设计目标

- 一个宝宝可以被多个用户共同记录
- 通过 6 位邀请码加入，不需要知道对方的手机号
- 三种角色覆盖不同权限需求（管理者/记录者/只读）
- 每条记录保留"谁记的"信息，时间线上可区分
- 对现有单用户流程零侵入（没有家庭成员时，体验和现在完全一样）

### 三、数据模型

#### 3.1 新增枚举：FamilyRole

```prisma
enum FamilyRole {
  admin    // 管理者：全部权限
  member   // 记录者：可记录、可查看、可撤销自己的记录
  viewer   // 只读：只能看，不能记录
}
```

#### 3.2 新增表：BabyMember

```prisma
model BabyMember {
  id        String     @id @default(uuid()) @db.Uuid
  babyId    String     @map("baby_id") @db.Uuid
  userId    String     @map("user_id") @db.Uuid
  role      FamilyRole @default(member)
  joinedAt  DateTime   @default(now()) @map("joined_at")
  createdAt DateTime   @default(now()) @map("created_at")
  updatedAt DateTime   @updatedAt @map("updated_at")

  baby Baby @relation(fields: [babyId], references: [id], onDelete: Cascade)
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([babyId, userId])                    // 同一宝宝同一用户只能有一条
  @@index([userId])                              // 按用户查"我加入了哪些宝宝"
  @@index([babyId])                              // 按宝宝查"这个宝宝有哪些成员"
  @@map("baby_members")
}
```

#### 3.3 新增表：InviteCode

```prisma
model InviteCode {
  id        String   @id @default(uuid()) @db.Uuid
  code      String   @unique               // 6位大写字母+数字
  babyId    String   @map("baby_id") @db.Uuid
  createdBy String   @map("created_by") @db.Uuid
  expiresAt DateTime @map("expires_at")
  usedCount Int      @default(0) @map("used_count")
  maxUses   Int      @default(10) @map("max_uses")   // 最多可被使用次数
  createdAt DateTime @default(now()) @map("created_at")

  baby    Baby @relation(fields: [babyId], references: [id], onDelete: Cascade)
  creator User @relation("inviteCreator", fields: [createdBy], references: [id])

  @@index([babyId])
  @@map("invite_codes")
}
```

设计说明：
- `code` 是 6 位大写字母+数字（排除易混淆的 0/O、1/I/L），约 167 万种组合，碰撞概率极低
- `expiresAt` 默认创建后 7 天过期
- `maxUses` 默认 10 次，防止邀请码被无限传播
- `usedCount` 记录已使用次数，到达 `maxUses` 后自动失效
- 一个宝宝同一时间可以有多个有效邀请码（爸爸生成一个，妈妈也可以生成一个）

#### 3.4 Baby 和 User 模型新增关系

```prisma
model Baby {
  // ... 已有字段不变
  members     BabyMember[]                        // ← 新增
  inviteCodes InviteCode[]                        // ← 新增
}

model User {

}
```

#### 3.5 完整 Schema 变化一览


### 四、权限体系

#### 4.1 角色权限矩阵

| 操作 | owner | admin | member | viewer |
|------|:-----:|:-----:|:------:|:------:|
| 查看宝宝信息 | ✅ | ✅ | ✅ | ✅ |
| 查看记录列表和统计 | ✅ | ✅ | ✅ | ✅ |
| 创建护理记录 | ✅ | ✅ | ✅ | ❌ |
| 撤销**自己**的记录 | ✅ | ✅ | ✅ | — |
| 撤销**他人**的记录 | ✅ | ✅ | ❌ | ❌ |
| 编辑宝宝档案 | ✅ | ✅ | ❌ | ❌ |
| 生成邀请码 | ✅ | ✅ | ❌ | ❌ |
| 修改成员角色 | ✅ | ✅ | ❌ | ❌ |
| 移除成员 | ✅ | ✅ | ❌ | ❌ |
| 删除宝宝档案 | ✅ | ❌ | ❌ | ❌ |

说明：
- `owner` = Baby.ownerId 对应的用户，是宝宝的创建者，拥有最高权限
- `admin` 由 owner 授权，权限几乎等同 owner（但不能删除宝宝）
- `member` 是日常记录者（如爷爷奶奶、月嫂），能记能看
- `viewer` 是只想看看的人（如远方的亲戚）

#### 4.2 后端权限校验中间件

在 auth 模块的 `authenticate` 基础上，新增两个可组合的权限检查函数：

```typescript
// plugins/permission.ts

/**
 * 检查当前用户是否是宝宝的 owner 或指定角色的成员
 * 用法: preHandler: [app.authenticate, app.requireBabyAccess('admin')]
 */
app.decorate('requireBabyAccess', (requiredRole?: FamilyRole) => {
  return async (request, reply) => {
    const userId = request.user.userId
    const babyId = request.params.babyId || request.body?.babyId || request.query?.babyId

    if (!babyId) return reply.code(400).send({ message: '缺少 babyId' })

    // 1. 检查是否是 owner
    const baby = await app.prisma.baby.findFirst({
      where: { id: babyId, ownerId: userId }
    })
    if (baby) {
      request.user.role = 'owner'
      request.user.babyId = babyId
      return // owner 拥有最高权限，直接放行
    }

    // 2. 检查是否是成员
    const member = await app.prisma.babyMember.findUnique({
      where: { babyId_userId: { babyId, userId } }
    })

    if (!member) return reply.code(403).send({ message: '无权访问该宝宝' })

    // 3. 角色权限校验
    if (requiredRole) {
      const roleHierarchy = { admin: 3, member: 2, viewer: 1 }
      if (roleHierarchy[member.role] < roleHierarchy[requiredRole]) {
        return reply.code(403).send({ message: '权限不足' })
      }
    }

    request.user.role = member.role
    request.user.babyId = babyId
  }
})

// 扩展类型
declare module 'fastify' {
  interface FastifyRequest {
    user: {
      userId: string
      phone?: string
      role?: 'owner' | FamilyRole
      babyId?: string
    }
  }
}
```

### 五、邀请码机制

#### 5.1 邀请码生成算法

```typescript
// 字符集：排除易混淆字符 0/O/1/I/L
const CHARSET = 'ABCDEFGHJKMNPQRSTUVWXYZ23456789'  // 29个字符

function generateCode(): string {
  const bytes = crypto.randomBytes(6)
  let code = ''
  for (let i = 0; i < 6; i++) {
    code += CHARSET[bytes[i] % CHARSET.length]
  }
  return code
}

// 碰撞概率: (1/29)^6 ≈ 1/594,823,321，极低
// 加上 UNIQUE 约束，即使碰撞也会触发重试
```

#### 5.2 邀请码生命周期

```
生成
  │  调用者必须是 owner 或 admin
  │  有效期: 7天
  │  最大使用次数: 10
  │
  ▼
有效状态
  │  其他用户输入邀请码 → POST /family/join
  │  校验: 存在 + 未过期 + usedCount < maxUses + 不是自己加入自己
  │  成功: usedCount++，创建 BabyMember(role=member)
  │  如果 usedCount === maxUses → 自动失效
  │
  ▼
失效（三种原因）
  ├── 过期: expiresAt < now
  ├── 用满: usedCount >= maxUses
  └── 手动作废: owner/admin 调用 DELETE /family/invite-code
```

```typescript
  // === 计算属性 ===
  const memberCount = computed(() => members.value.length)
  const hasMembers = computed(() => members.value.length > 1)  // > 1 表示有其他成员

  const myMember = computed(() => {
    const authStore = useAuthStore()
    return members.value.find(m => m.user.id === authStore.user?.id)
  })

  const myRole = computed<'owner' | FamilyRole | null>(() => {
    const m = myMember.value
    return m?.isOwner ? 'owner' : m?.role ?? null
  })

  const canManageMembers = computed(() =>
    myRole.value === 'owner' || myRole.value === 'admin'
  )

  const canRecord = computed(() =>
    myRole.value === 'owner' || myRole.value === 'admin' || myRole.value === 'member'
  )

  // === 方法 ===

  /** 获取成员列表 */
  const fetchMembers = async (babyId: string) => {
    isLoading.value = true
    try {
      const res = await apiGetMembers(babyId)
      members.value = res.members
    } finally {
      isLoading.value = false
    }
  }

  /** 生成邀请码 */
  const generateInviteCode = async (babyId: string): Promise<InviteCode> => {
    const res = await apiGenerateInviteCode(babyId)
    inviteCodes.value.push(res)
    return res
  }

  /** 获取有效邀请码 */
  const fetchInviteCodes = async (babyId: string) => {
    const res = await apiGetInviteCodes(babyId)
    inviteCodes.value = res.codes
  }

  /** 作废邀请码 */
  const revokeInviteCode = async (code: string) => {
    await apiRevokeInviteCode(code)
    inviteCodes.value = inviteCodes.value.filter(c => c.code !== code)
  }

  /** 通过邀请码加入 */
  const joinByCode = async (code: string): Promise<JoinedResult> => {
    const res = await apiJoinByCode(code)
    // 加入成功后刷新可访问宝宝列表
    const babyStore = useBabyStore()
    await babyStore.loadAccessibleBabies()
    return res
  }

  /** 修改成员角色 */
  const changeRole = async (memberId: string, role: FamilyRole) => {
    await apiChangeRole(memberId, role)
    const idx = members.value.findIndex(m => m.id === memberId)
    if (idx !== -1) members.value[idx].role = role
  }

  /** 移除成员 */
  const removeMember = async (memberId: string) => {
    await apiRemoveMember(memberId)
    members.value = members.value.filter(m => m.id !== memberId)
  }

  /** 主动退出 */
  const leave = async (babyId: string) => {
    await apiLeave(babyId)
    members.value = []
    const babyStore = useBabyStore()
    await babyStore.loadAccessibleBabies()
  }

  /** 清空（切换宝宝或退出登录时调用） */
  const reset = () => {
    members.value = []
    inviteCodes.value = []
  }

  return {
    members, inviteCodes, isLoading,
    memberCount, hasMembers, myRole, canManageMembers, canRecord,
    fetchMembers, generateInviteCode, fetchInviteCodes, revokeInviteCode,
    joinByCode, changeRole, removeMember, leave, reset
  }
})
```

```typescript
  const authStore = useAuthStore()
  const babyStore = useBabyStore()
```

### 十、安全与边界

#### 10.1 安全防护

| 风险 | 防护措施 |
|------|---------|
| 暴力猜解邀请码 | 6 位码 + 7 天过期 + 10 次上限；可选加 IP 频率限制 |
| 邀请码泄露 | owner/admin 可随时作废；用满自动失效 |
| 被踢出后缓存数据 | 退出/被移除时清除该宝宝的所有 localStorage |
| 多人同时操作冲突 | clientId 幂等保证不重复；软删除不物理删除 |
| 权限提升攻击 | 角色校验在每次 API 调用时实时执行，不依赖前端缓存 |

#### 10.2 边界情况

| 场景 | 处理方式 |
|------|---------|
| owner 退出登录 | 不影响其他成员，宝宝数据保留 |
| 最后一个成员被移除 | 宝宝仍然存在，owner 可重新邀请 |
| 加入时已经是 owner | 返回 400 "不能加入自己创建的宝宝" |
| 加入时已有该宝宝 | 返回 400 "你已经是该宝宝的成员" |
| 邀请码过期后有人尝试加入 | 返回 400 "邀请码不存在或已过期" |
| 多人同时生成邀请码 | 允许，每个成员可以有自己的邀请码 |
| owner 删除宝宝 | Cascade 删除所有 BabyMember、InviteCode、CareRecord |
