## BabyStar 用户账号与鉴权模块 — 架构设计

> 本文档定义了 BabyStar 的用户账号体系与鉴权机制，覆盖数据库变更、后端鉴权链路、前端状态管理和页面设计。

---

### 一、设计原则

1. **渐进式复杂度**：MVP 阶段用手机号+密码（零成本），接口设计预留短信验证码和微信登录的扩展位
2. **双 Token 机制**：Access Token（短期 JWT）+ Refresh Token（长期、数据库存储、旋转刷新），兼顾安全和体验
3. **最小侵入改造**：新增 `auth` 模块，不改已有模块的业务逻辑，仅在每个路由入口加鉴权钩子
4. **离线友好**：Token 持久化在 localStorage，App 启动时尝试刷新；离线期间允许本地操作，联网后同步

---

### 三、数据库变更

#### 3.1 User 模型新增字段

```prisma
model User {
  id           String   @id @default(uuid()) @db.Uuid
  phone        String?  @unique
  email        String?  @unique
  nickname     String?
  passwordHash String?  @map("password_hash")   // ← 新增
  createdAt    DateTime @default(now()) @map("created_at")
  updatedAt    DateTime @updatedAt @map("updated_at")

  babies  Baby[]
  records CareRecord[]
  refreshTokens RefreshToken[]                   // ← 新增关系

  @@map("users")
}
```

设计说明：
- `passwordHash` 可空，为未来微信登录（无密码）留余地
- 手机号注册时 phone 必填，微信注册时 phone 可后续绑定

#### 3.2 新增 RefreshToken 模型

```prisma
model RefreshToken {
  id        String   @id @default(uuid()) @db.Uuid
  token     String   @unique                // 随机字符串，用于查询
  userId    String   @db.Uuid
  expiresAt DateTime @map("expires_at")
  createdAt DateTime @default(now()) @map("created_at")

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@map("refresh_tokens")
}
```

设计说明：
- 一个用户可以有多个 RefreshToken（多设备登录）
- `onDelete: Cascade`：用户注销时自动清除所有 Token
- `expiresAt` 用于定期清理过期 Token（定时任务或惰性清理）

#### 4.3 Auth 插件

新建 `plugins/auth.ts`：

```typescript
// 核心逻辑伪代码

import fp from 'fastify-plugin'
import jwt from '@fastify/jwt'
import cookie from '@fastify/cookie'

// 白名单路由（不需要鉴权）
const WHITELIST = [
  '/health',
  '/api/auth/register',
  '/api/auth/login',
  '/api/auth/refresh',
]

export const authPlugin = fp(async (app) => {
  // 1. 注册 JWT 插件
  await app.register(jwt, {
    secret: config.jwtSecret,
    sign: { expiresIn: config.jwtExpiresIn }
  })

  // 2. 注册 Cookie 插件
  await app.register(cookie, {
    secret: config.refreshSecret,
    parseOptions: {}
  })

  // 3. 扩展 FastifyRequest 类型
  app.decorate('authenticate', async (request, reply) => {
    // 白名单放行
    if (WHITELIST.some(path => request.url.startsWith(path))) return

    try {
      // 从 Authorization header 解析并验证 JWT
      const decoded = await request.jwtVerify()
      // 将用户信息挂到 request 上
      request.user = { userId: decoded.userId, phone: decoded.phone }
    } catch (err) {
      reply.code(401).send({ message: '未登录或 Token 已过期' })
    }
  })
})
```

##### 注册 `POST /api/auth/register`

```
请求 Body:
{
  "phone": "13800138000",       // 11位手机号
  "password": "MyP@ss123",      // 8-32位，含字母和数字
  "nickname": "小星星妈妈"       // 可选
}

成功响应 201:
{
  "user": {
    "id": "uuid",
    "phone": "138****8000",     // 脱敏返回
    "nickname": "小星星妈妈"
  },
  "accessToken": "eyJhbG...",   // JWT，2小时有效
  "refreshToken": "rt_xK9..."   // 随机字符串，30天有效
}

失败响应 400:
{ "message": "手机号已注册" }
{ "message": "密码格式不符合要求" }
```

业务逻辑：
```
1. Zod 校验输入格式
2. 查询 phone 是否已存在 → 存在则 400
3. bcrypt.hash(password, 10) → passwordHash
4. prisma.user.create({ phone, passwordHash, nickname })
5. 签发 accessToken (JWT, 含 userId)
6. 生成 refreshToken (crypto.randomUUID), 写入 refresh_tokens 表
7. 同时设置 refreshToken 到 httpOnly cookie
8. 返回 user + accessToken + refreshToken
```

##### 登录 `POST /api/auth/login`

```
请求 Body:
{
  "phone": "13800138000",
  "password": "MyP@ss123"
}

成功响应 200:
{
  "user": { "id": "uuid", "phone": "138****8000", "nickname": "..." },
  "accessToken": "eyJhbG...",
  "refreshToken": "rt_xK9..."
}

失败响应 401:
{ "message": "手机号或密码错误" }
```

业务逻辑：
```
1. 查询 user by phone
2. 不存在 → 401 "手机号或密码错误"（不泄露是否注册）
3. bcrypt.compare(password, user.passwordHash)
4. 不匹配 → 401 "手机号或密码错误"
5. 签发 accessToken + 生成 refreshToken（同注册流程）
```

##### 刷新 `POST /api/auth/refresh`

```
请求 Body 或 Cookie:
{ "refreshToken": "rt_xK9..." }
或 Cookie: refreshToken=rt_xK9...

成功响应 200:
{
  "accessToken": "eyJhbG...(新的)",
  "refreshToken": "rt_new..."   // 旋转刷新：旧 Token 失效，签发新 Token
}

失败响应 401:
{ "message": "Refresh Token 无效或已过期" }
```

业务逻辑：
```
1. 从 body 或 cookie 获取 refreshToken
2. 查询 refresh_tokens 表（by token, 检查 expiresAt > now）
3. 不存在或已过期 → 401
4. 删除旧 refreshToken（旋转刷新，防止重放）
5. 签发新 accessToken + 生成新 refreshToken
6. 设置新 refreshToken 到 httpOnly cookie
7. 返回新双 Token
```

设计要点——旋转刷新：每次 refresh 都删除旧 Token、签发新 Token。如果检测到已失效的 Token 被再次使用（可能是泄露），可以额外清除该用户的所有 RefreshToken（强制全部重新登录）。

##### 退出 `POST /api/auth/logout`

```
请求 Header: Authorization: Bearer <accessToken>
请求 Body: { "refreshToken": "rt_xK9..." }  (可选)

成功响应 200:
{ "message": "已退出登录" }
```

业务逻辑：
```
1. 删除指定 refreshToken（如果提供）
2. 清除 refreshToken cookie
3. 返回成功（即使 Token 不存在也返回成功，避免信息泄露）
```

### 五、前端鉴权状态管理

#### 5.1 Auth Store

新建 `src/stores/auth.ts`：

```typescript
export const useAuthStore = defineStore('auth', () => {
  // === 状态 ===
  const accessToken = ref<string | null>(localStorage.getItem('access_token'))
  const refreshToken = ref<string | null>(localStorage.getItem('refresh_token'))
  const user = ref<{ id: string; phone: string; nickname: string | null } | null>(null)
  const isLoading = ref(false)

  // === 计算属性 ===
  const isLoggedIn = computed(() => !!accessToken.value)

  // === 方法 ===

  /** 登录 */
  const login = async (phone: string, password: string) => {
    const res = await apiLogin(phone, password)
    setTokens(res.accessToken, res.refreshToken)
    user.value = res.user
  }

  /** 注册 */
  const register = async (phone: string, password: string, nickname?: string) => {
    const res = await apiRegister(phone, password, nickname)
    setTokens(res.accessToken, res.refreshToken)
    user.value = res.user
  }

  /** 退出登录 */
  const logout = async () => {
    try { await apiLogout(refreshToken.value) } catch { /* 忽略 */ }
    clearTokens()
    user.value = null
  }

  /** 刷新 Token（自动重试 401 时调用） */
  const refresh = async (): Promise<boolean> => {
    if (!refreshToken.value) return false
    try {
      const res = await apiRefresh(refreshToken.value)
      setTokens(res.accessToken, res.refreshToken)
      return true
    } catch {
      clearTokens()
      return false
    }
  }

  /** 启动时检查登录状态 */
  const checkAuth = async () => {
    if (!accessToken.value) return
    try {
      const me = await apiGetMe()     // GET /auth/me
      user.value = me
    } catch {
      // accessToken 过期，尝试刷新
      const ok = await refresh()
      if (ok) {
        const me = await apiGetMe()
        user.value = me
      }
    }
  }

  // === 内部方法 ===

  const setTokens = (at: string, rt: string) => {
    accessToken.value = at
    refreshToken.value = rt
    localStorage.setItem('access_token', at)
    localStorage.setItem('refresh_token', rt)
  }

  const clearTokens = () => {
    accessToken.value = null
    refreshToken.value = null
    user.value = null
    localStorage.removeItem('access_token')
    localStorage.removeItem('refresh_token')
    localStorage.removeItem('baby_profile')
    localStorage.removeItem('today_records')
    localStorage.removeItem('pending_records')
  }

  return {
    accessToken, refreshToken, user, isLoading, isLoggedIn,
    login, register, logout, refresh, checkAuth
  }
})
```

#### 5.2 API 层改造

在 `src/utils/api.ts` 中做以下修改：

```typescript
// 1. 移除 DEFAULT_USER_ID（不再需要）

// 2. 新增：请求拦截器（给每个 fetch 调用自动加 Authorization）
const authHeaders = (): Record<string, string> => {
  const token = localStorage.getItem('access_token')
  return token ? { Authorization: `Bearer ${token}` } : {}
}

// 3. 封装通用 fetch 函数，处理 401 自动刷新
const apiFetch = async (url: string, options: RequestInit = {}): Promise<any> => {
  const headers = {
    'Content-Type': 'application/json',
    ...authHeaders(),
    ...(options.headers as Record<string, string> || {})
  }

  let response = await fetch(url, { ...options, headers })

  // 401 → 尝试刷新 Token 并重试一次
  if (response.status === 401) {
    const authStore = useAuthStore()
    const refreshed = await authStore.refresh()
    if (refreshed) {
      headers.Authorization = `Bearer ${localStorage.getItem('access_token')}`
      response = await fetch(url, { ...options, headers })
    } else {
      // 刷新失败 → 跳转登录
      router.push('/login')
      throw new Error('未登录')
    }
  }

  if (!response.ok) {
    const body = await response.json().catch(() => ({}))
    throw new Error(body.message || `请求失败 (${response.status})`)
  }

  return response.json()
}

// 4. 改造所有 API 函数使用 apiFetch，移除 userId 参数
// 例: submitRecord 不再传 userId
// 例: getBabies() 不再传 userId query（后端从 JWT 获取）
// 例: createBaby() 不再传 userId

// 5. 新增 Auth API 函数
export const apiLogin = (phone: string, password: string) =>
  apiFetch(`${API_BASE_URL}/auth/login`, {
    method: 'POST', body: JSON.stringify({ phone, password })
  })

export const apiRegister = (phone: string, password: string, nickname?: string) =>
  apiFetch(`${API_BASE_URL}/auth/register`, {
    method: 'POST', body: JSON.stringify({ phone, password, nickname })
  })

export const apiRefresh = (refreshToken: string) =>
  apiFetch(`${API_BASE_URL}/auth/refresh`, {
    method: 'POST', body: JSON.stringify({ refreshToken })
  })

export const apiLogout = (refreshToken: string | null) =>
  apiFetch(`${API_BASE_URL}/auth/logout`, {
    method: 'POST', body: JSON.stringify({ refreshToken })
  })

export const apiGetMe = () =>
  apiFetch(`${API_BASE_URL}/auth/me`)
```

#### 5.4 App.vue 路由守卫改造

```typescript
// 三级守卫逻辑

router.beforeEach(async (to) => {
  const authStore = useAuthStore()
  const babyStore = useBabyStore()

  // 1. 检查登录状态（仅首次或 Token 存在但未验证时）
  if (authStore.isLoggedIn && !authStore.user) {
    await authStore.checkAuth()
  }

  // 2. 需要登录的页面 + 未登录 → /login
  if (to.meta.requiresAuth && !authStore.isLoggedIn) {
    return { path: '/login', query: { redirect: to.fullPath } }
  }

  // 3. 已登录 + 无宝宝档案 + 不在创建页 → /profile/create
  if (authStore.isLoggedIn && !babyStore.hasProfile && to.path !== '/profile/create') {
    return { path: '/profile/create' }
  }

  // 4. 已登录 + 有宝宝 + 在登录/注册/创建页 → /
  if (authStore.isLoggedIn && babyStore.hasProfile &&
      ['/login', '/register', '/profile/create'].includes(to.path)) {
    return { path: '/' }
  }
})
```

### 七、Token 生命周期

```
用户注册/登录
    │
    ├─→ 签发 accessToken (JWT, 2h)  → localStorage('access_token')
    │   └─ Header: { alg: HS256 }
    │   └─ Payload: { userId, phone, iat, exp }
    │
    └─→ 签发 refreshToken (UUID)    → localStorage('refresh_token') + DB
        └─ 有效期: 30天

正常使用（2小时内）
    │
    └─→ 每个请求: Authorization: Bearer <accessToken>
        后端 jwtVerify → request.user.userId

Token 过期（2小时后）
    │
    ├─→ 前端 fetch 收到 401
    ├─→ apiFetch 自动调用 refresh()
    │   ├─→ POST /auth/refresh { refreshToken }
    │   ├─→ 后端验证 refreshToken → 删除旧 Token → 签发新双 Token
    │   └─→ 前端更新 localStorage → 重试原请求（对业务代码透明）
    │
    └─→ refresh 也失败
        ├─→ 清除所有 Token
        └─→ 跳转 /login

退出登录
    │
    ├─→ POST /auth/logout { refreshToken }
    ├─→ 后端删除 refreshToken
    └─→ 前端清除所有本地存储
```

### 八、安全设计

#### 8.1 密码安全

- 使用 bcrypt，cost factor = 10（约 100ms/次，足够安全且不影响体验）
- 不存储明文密码，不存储可逆加密
- 错误提示统一为"手机号或密码错误"，不泄露手机号是否已注册

#### 8.2 Token 安全

- Access Token 有效期 2 小时，降低泄露风险
- Refresh Token 旋转刷新，每次使用后立即失效
- Refresh Token 存入数据库，支持主动吊销（用户退出/改密时）
- 可选增强：检测已失效 Refresh Token 被重用 → 清除该用户所有 Token（疑似泄露）

#### 8.3 传输安全

- 生产环境强制 HTTPS（HSTS）
- CORS 配置明确允许的 origin（不用 `*`）
- 生产环境 `JWT_SECRET` 和 `REFRESH_SECRET` 使用环境变量，不硬编码

#### 8.4 手机号脱敏

- 所有返回给前端的手机号统一脱敏：`138****8000`
- 数据库存储完整手机号

#### 8.5 防护策略（后续增强）

- 登录频率限制：同一手机号 5 分钟内最多 5 次尝试
- IP 频率限制：同一 IP 1 小时内最多 20 次登录尝试
- 注册频率限制：同一 IP 1 小时内最多 3 次注册
