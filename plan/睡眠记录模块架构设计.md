# BabyStar 睡眠记录模块 — 架构设计

> 本文档定义了 BabyStar 的睡眠记录模块，覆盖数据模型扩展、后端 API 改造、前端睡眠卡片组件、计时器状态管理和统计页联动。
> 前置依赖：用户认证模块、核心记录模块已完成。

## 用户决策确认

- **交互方式**：同时支持计时器模式（一键开始/结束）和手动填写模式（补录过去时间）
- **记录维度**：精简版 — 入睡时间、醒来时间、时长、备注
- **首页布局**：睡眠卡片替换现有喂养计时器位置，保持 2列2行 奶粉/母乳/拉尿/拉屎 不变

---

### 一、场景与问题定义

#### 1.1 目标场景

新生儿（0-3 个月）每天睡眠 14-17 小时，分为 6-8 次小睡。父母核心需求：
- 快速记录每次睡眠的入睡和醒来时间（抱睡时单手操作）
- 实时了解宝宝当前是"清醒"还是"睡眠中"，以及持续了多久
- **清醒窗口（wake window）**：知道距离上次醒来过了多久，判断是否该放下宝宝睡觉（新生儿清醒窗口仅 45-90 分钟，超过会导致过度疲劳）

#### 1.2 当前问题

BabyStar 当前首页的 TimerCard 仅显示"距上次喂奶"的计时，而睡眠是同等高频的记录需求，且缺少专门的计时 UI。喂养计时器对新生儿父母的价值远不如清醒窗口计时器。

#### 1.3 设计目标

| 目标 | 约束 |
|------|------|
| 支持计时模式（一键开始/结束）和手动补录模式 | 与现有记录模式保持一致的交互范式 |
| 首页睡眠卡片同时承担"清醒窗口"和"睡眠计时"双重职责 | 替换现有喂养计时器位置，不增加额外卡片 |
| 数据模型最小化扩展 | 复用 CareRecord 通用字段，仅新增 endedAt 字段 |
| 离线容忍 | 计时器状态持久化到 localStorage，离线可开始/结束，联网后同步 |

### 三、数据模型

#### 3.1 CareEventType 枚举新增

```prisma
enum CareEventType {
  poop
  pee
  breastfeeding
  formula
  sleep        // 新增
}
```

#### 3.2 CareRecord 新增 endedAt 字段

```prisma
model CareRecord {
  id          String        @id @default(cuid())
  clientId    String        @unique
  babyId      String
  userId      String
  eventType   CareEventType
  happenedAt  DateTime      // 睡眠开始时间
  endedAt     DateTime?     // ★ 新增：睡眠结束时间
  duration    Int?          // 睡眠时长（分钟）
  side        BreastSide?
  amount      Int?
  note        String?
  source      RecordSource  @default(pwa)
  deletedAt   DateTime?
  createdAt   DateTime      @default(now())
  updatedAt   DateTime      @updatedAt
  // ... relations unchanged
}
```

#### 3.3 sleep 类型字段使用说明

| 字段 | sleep 含义 | 是否必填 |
|------|-----------|---------|
| `happenedAt` | 入睡时间 | 是 |
| `endedAt` | 醒来时间 | 计时模式必填，手动模式可推算 |
| `duration` | 睡眠时长（分钟） | 是（计时自动算，手动手动输） |
| `note` | 备注 | 否 |
| `side` | 不使用 | — |
| `amount` | 不使用 | — |

#### 3.4 endedAt 的设计理由

- **查询清晰**：`WHERE endedAt IS NULL` 直接定位活跃睡眠，无需 `happenedAt + duration > now()` 计算
- **跨午夜准确**：endedAt 精确记录结束时刻，不依赖 duration 推算
- **向后兼容**：字段可选（`DateTime?`），不影响已有四类记录
- **冗余可控**：duration 保持为冗余存储字段，前端和 stats 无需每次做时间差计算

#### 3.5 Schema 变更一览

| 变更 | 类型 | 影响 |
|------|------|------|
| CareEventType 增加 `sleep` | 枚举扩展 | 所有使用该枚举的查询自动支持 |
| CareRecord 增加 `endedAt DateTime?` | 字段新增 | 已有记录 endedAt=null，无影响 |

### 四、核心机制：睡眠计时器状态机

#### 4.1 状态定义

```
         ┌──────────────────────────┐
         │                          │
         ▼                          │
   ┌──────────┐   点击"结束睡眠"   ┌──────────┐
   │  AWAKE   │ ─────────────────▶ │ SLEEPING │
   │ (清醒中)  │                    │ (睡眠中)  │
   └──────────┘ ◀───────────────── └──────────┘
         ▲      自动（记录完成）          │
         │                              │
         └──────────────────────────────┘

AWAKE 状态:
  - 显示: "清醒 X小时Y分钟"
  - 计算: now() - lastSleep.endedAt
  - 按钮: "开始睡眠"（主按钮）+ "手动记录"（文字链接）
  - 刷新: 每60秒更新清醒时长

SLEEPING 状态:
  - 显示: "睡眠中 X小时Y分钟" + 脉冲动画
  - 计算: now() - currentSleep.happenedAt
  - 按钮: "结束睡眠"（红色描边按钮）
  - 刷新: 每60秒更新已睡时长
  - 持久化: startedAt 写入 localStorage 防丢失
```

#### 4.2 清醒窗口计算逻辑

```typescript
// 获取最近一次已结束的睡眠
const lastSleep = await getLastSleep(babyId)
// 优先使用 endedAt，其次 happenedAt + duration
const wakeStart = lastSleep.endedAt
  ? new Date(lastSleep.endedAt)
  : new Date(new Date(lastSleep.happenedAt).getTime() + (lastSleep.duration || 0) * 60000)
// 清醒窗口 = 当前时间 - wakeStart
const wakeWindowMin = Math.round((Date.now() - wakeStart.getTime()) / 60000)
```

#### 4.3 离线与恢复策略

```
离线开始睡眠:
  → startedAt 写入 localStorage
  → 计时器正常运行（不依赖网络）

离线结束睡眠:
  → 记录写入现有 pending_records 离线队列
  → 联网后由 App.vue 的 syncPendingRecords() 统一同步

页面刷新恢复:
  → sleepTimerStore.init() 先读 localStorage
  → 若有活跃计时，恢复 startedAt 并重启 setInterval
  → 若无本地状态，查后端 activeSleep 接口（endedAt=null）
```

#### 5.2 记录更新（PUT）字段清理逻辑扩展

```typescript
// 现有 if/else 链增加 sleep 分支
} else if (input.eventType === 'sleep') {
  data.duration = input.duration
  data.endedAt = input.endedAt
  data.side = null
  data.amount = null
  // 智能推算：只给了一个，自动算另一个
  if (input.duration && !input.endedAt) {
    data.endedAt = new Date(new Date(input.happenedAt).getTime() + input.duration * 60000)
  } else if (!input.duration && input.endedAt) {
    data.duration = Math.round(
      (new Date(input.endedAt).getTime() - new Date(input.happenedAt).getTime()) / 60000
    )
  }
}
```

#### 5.3 新增两个查询端点

##### GET /api/records/last-sleep?babyId=xxx

返回最近一条已结束的睡眠记录（`endedAt IS NOT NULL`），用于清醒窗口计算。无记录返回 `null`。

##### GET /api/records/active-sleep?babyId=xxx

返回当前活跃睡眠记录（`endedAt IS NULL`），用于页面刷新后恢复计时器状态。无记录返回 `null`。

#### 5.4 每日统计接口扩展

  sleepCount: records.filter(r => r.eventType === 'sleep').length,  // ★ 新增

#### 6.1 新建 sleepTimerStore（Pinia）

文件：`src/stores/sleepTimer.ts`（新建）

核心 API：
```typescript
const useSleepTimerStore = defineStore('sleepTimer', () => {
  // State
  const isActive = ref(false)
  const startedAt = ref<string | null>(null)
  const elapsedMinutes = ref(0)       // 睡眠中：已睡分钟数
  const wakeWindowMinutes = ref(0)    // 清醒中：已醒分钟数

  // Computed
  const elapsedDisplay = computed(() => formatMinutes(elapsedMinutes.value))
  const wakeWindowDisplay = computed(() => formatMinutes(wakeWindowMinutes.value))

  // Actions
  async function init(babyId: string)          // 恢复状态
  function startSleep()                         // 开始睡眠
  async function endSleep(babyId: string)       // 结束睡眠→创建记录
  async function refreshWakeWindow(babyId: string)  // 刷新清醒窗口

  return { isActive, startedAt, elapsedMinutes, wakeWindowMinutes,
           elapsedDisplay, wakeWindowDisplay,
           init, startSleep, endSleep, refreshWakeWindow }
})

 │                       │ endSleep()               │                 │
 │                       │ → 计算 duration          │                 │
 │                       │ → POST /api/records ────▶│ INSERT ────────▶│
 │                       │◀─────────────────────────│◀────────────────│
 │                       │ → isActive=false         │                 │
 │                       │ → localStorage.clear()   │                 │
 │                       │                          │                 │
 │  [可选备注对话框]       │                          │                 │
 │  输入备注 → PUT ──────▶│─────────────────────────▶│ UPDATE ────────▶│
```

#### 8.2 跨午夜处理

```
场景: 宝宝 23:00 入睡，次日 01:30 醒来

happenedAt = 2026-06-30T23:00:00
endedAt   = 2026-07-01T01:30:00
duration  = 150 分钟

统计归属: 按 happenedAt 日期 → 计入 6月30日
原因: "昨晚的睡眠"算在昨天，符合父母直觉
现有查询已按 happenedAt 过滤，无需额外修改
```

### 九、安全与边界

| 边界情况 | 处理策略 | 实现位置 |
|---------|---------|---------|
| 重复点击"开始睡眠" | `if (isActive) return` 防重入 | sleepTimerStore.startSleep() |
| 页面刷新后恢复计时 | init() 先读 localStorage，再查后端 activeSleep | sleepTimerStore.init() |
| 离线时开始/结束睡眠 | localStorage 持久化 + pending_records 离线队列 | sleepTimerStore + App.vue |
| 跨午夜睡眠 | 按 happenedAt 日期归属统计 | 后端已有逻辑 |
| 极短睡眠（<1分钟） | `Math.max(1, duration)` 保底1分钟 | endSleep() |
| 极长睡眠（>12小时） | 前端 Stepper max=720 + 后端 validation max=720 | 前后端双层校验 |
| 手动记录时间在未来 | DateTimePicker max=当前时间 | 手动记录对话框 |
| 多 Tab 同时打开 | localStorage 事件跨 Tab 同步 | sleepTimerStore |
| 误结束（太早点了） | Stats 页编辑对话框可调整 duration 和 endedAt | Stats.vue |
| 切换宝宝 | localStorage key 按 babyId 隔离 | `babystar_sleep_timer_{babyId}` |
