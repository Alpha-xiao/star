# BabyStar 前端权限拦截设计

## 背景

BabyStar 后端已经基于宝宝访问关系实现权限校验，前端需要补齐入口禁用、操作拦截和友好提示，避免用户在无权限场景下误操作。

前端权限拦截只负责体验优化，后端仍是最终权限边界。

## 角色定义

| 角色 | 含义 |
| --- | --- |
| `owner` | 宝宝创建者，拥有最高权限 |
| `admin` | 管理员，可管理档案、成员和记录 |
| `member` | 记录者，可新增记录，只能编辑/撤销自己创建的记录 |
| `viewer` | 只读成员，只能查看记录、统计和档案 |

## 权限矩阵

| 能力 | owner | admin | member | viewer |
| --- | --- | --- | --- | --- |
| 查看首页 | 是 | 是 | 是 | 是 |
| 查看统计/明细 | 是 | 是 | 是 | 是 |
| 新增护理记录 | 是 | 是 | 是 | 否 |
| 编辑自己的记录 | 是 | 是 | 是 | 否 |
| 编辑他人记录 | 是 | 是 | 否 | 否 |
| 撤销自己的记录 | 是 | 是 | 是 | 否 |
| 撤销他人记录 | 是 | 是 | 否 | 否 |
| 查看宝宝档案 | 是 | 是 | 是 | 是 |
| 编辑宝宝档案 | 是 | 是 | 否 | 否 |
| 查看家庭成员 | 是 | 是 | 是 | 是 |
| 生成/作废邀请码 | 是 | 是 | 否 | 否 |
| 修改成员角色 | 是 | 是 | 否 | 否 |
| 设置管理员 | 是 | 否 | 否 | 否 |
| 移除成员 | 是 | 是 | 否 | 否 |

## 设计原则

1. 权限来源统一从当前宝宝的访问关系推导，不依赖家庭成员列表是否已加载。
2. 页面入口可禁用，但关键提交函数必须二次兜底。
3. `viewer` 可以浏览数据，但所有写操作都提示只读。
4. `member` 可以记录，但不能编辑/撤销其他成员创建的记录。
5. 后端 403 统一提示“权限不足”，防止前端漏拦截时体验不清晰。

## 实现方案

### 1. Baby Store 统一暴露权限能力

在 `src/stores/baby.ts` 增加：

- `currentAccess`：当前宝宝在可访问列表中的关系记录。
- `currentRole`：当前宝宝角色，可能为 `owner/admin/member/viewer/null`。
- `canRecord`：是否可以新增护理记录。
- `canManageBaby`：是否可以编辑宝宝档案。
- `canManageFamily`：是否可以管理家庭成员和邀请码。
- `isReadOnly`：是否为只读成员。

### 2. 首页记录入口拦截

在 `src/views/home.vue` 中：

- 四个记录按钮对 `viewer` 显示禁用态。
- 点击禁用态按钮提示“当前为只读成员，不能记录”。
- `handleRecord` 提交前再次判断 `canRecord`。
- 路由 query action 打开弹窗前也先判断权限。

### 3. 统计页明细操作拦截

在 `src/views/Stats.vue` 中：

- `owner/admin` 可编辑和撤销所有记录。
- `member` 只能编辑和撤销自己创建的记录。
- `viewer` 只能查看。
- 无权限记录不显示撤销按钮，点击明细时给出提示。

### 4. 档案页编辑拦截

在 `src/views/profile.vue` 中：

- 只有 `owner/admin` 显示顶部编辑按钮和快捷操作中的“编辑档案”。
- `enterEdit` 与 `saveEdit` 内部均做权限兜底。
- 无权限用户仍可查看档案和家庭成员入口。

### 5. API 403 兜底提示

在 `src/utils/api.ts` 中统一处理 403：

- 写接口收到 403 时提示“权限不足，无法执行该操作”。
- 查询类接口继续抛错，由页面原有加载失败提示处理。

## 验收点

1. `viewer` 进入首页能看到按钮置灰，点击提示只读，不能新增记录。
2. `viewer` 在统计页不能编辑/撤销记录。
3. `member` 可以新增记录，可以编辑/撤销自己的记录。
4. `member` 点击他人记录提示“只能操作自己创建的记录”。
5. `owner/admin` 可以编辑和撤销所有记录。
6. `member/viewer` 在档案页看不到编辑档案入口。
7. 后端返回 403 时前端有明确权限不足提示。
