# 成长记录模块架构设计

> 宝宝体重、身高、头围的持续追踪，结合 WHO 标准百分位曲线，帮助家长科学评估宝宝发育状况。

## 1. 功能概述

### 1.1 核心价值

新生儿出生后，体重、身高、头围是衡量发育状况的三大核心指标。家长需要定期测量并记录，在儿保体检时向医生展示趋势曲线。当前 BabyStar 仅在宝宝档案中保存了出生体重和出生身高两个静态字段，缺少持续追踪能力。

### 1.2 功能范围

| 能力 | 说明 |
|------|------|
| 成长数据录入 | 体重(kg)、身高(cm)、头围(cm)，三项均为选填 |
| 成长曲线图 | 基于 WHO 标准，展示 P3/P15/P50/P85/P97 百分位参考线 + 宝宝实际数据线 |
| 发育评估 | 自动判定当前数据所处百分位区间，给出"发育正常/偏轻/偏重"提示 |
| 测量记录列表 | 时间线式历史记录，支持编辑和删除 |
| 档案页集成 | 宝宝档案页"成长数据概览"入口改为跳转成长记录页 |

### 1.3 不在范围内

- 生长曲线中不引入骨龄、胸围等低频指标
- 不做同龄宝宝对比（P3 阶段不考虑社交功能）
- 不做 AI 预测身高功能

## 2. 数据模型

### 2.1 新增 GrowthRecord 表

```prisma
model GrowthRecord {
  id        String   @id @default(uuid()) @db.Uuid
  clientId  String   @unique @map("client_id")
  babyId    String   @map("baby_id") @db.Uuid
  userId    String   @map("user_id") @db.Uuid
  measuredAt DateTime @map("measured_at")
  weight    Float?   // kg，精度 0.01，范围 0.5-30
  height    Float?   @map("height_cm")  // cm，精度 0.1，范围 30-150
  headCircumference Float? @map("head_circumference") // cm，精度 0.1，范围 25-60
  note      String?
  source    RecordSource @default(pwa)
  deletedAt DateTime? @map("deleted_at")
  createdAt DateTime  @default(now()) @map("created_at")
  updatedAt DateTime  @updatedAt @map("updated_at")

  baby Baby @relation(fields: [babyId], references: [id], onDelete: Cascade)
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([babyId, measuredAt(sort: Desc)])
  @@map("growth_records")
}
```

### 2.2 关联修改

Baby 模型新增关系：

```prisma

```

User 模型新增关系：


### 2.3 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 独立表 vs CareRecord 扩展 | 独立表 | 成长数据频率低（月级），语义独立于日常护理事件，混入 CareRecord 会污染枚举和查询 |
| 三项字段均 nullable | 是 | 降低录入压力，家长可能只测体重不测头围 |
| clientId 幂等 | 复用现有模式 | 与 CareRecord 一致的离线提交策略 |
| measuredAt vs happenedAt | measuredAt | 语义更准确，"测量时间"区别于护理事件的"发生时间" |
| 软删除 deletedAt | 复用现有模式 | 与 CareRecord 一致 |

## 4. WHO 生长标准数据

### 4.1 数据来源

WHO Child Growth Standards (2006)，覆盖 0-60 月龄，按性别分组。

### 4.2 前端静态数据

以 TypeScript 文件形式放在 `src/data/` 目录下，按月龄（0, 1, 2, ... 60）存储 P3/P15/P50/P85/P97 五个百分位值。

```typescript
// src/data/who-weight.ts
// 女宝体重 WHO 标准 (kg)
export const whoWeightGirl: WHOStandard[] = [
  { month: 0, p3: 2.4, p15: 2.8, p50: 3.2, p85: 3.7, p97: 4.0 },
  { month: 1, p3: 2.9, p15: 3.3, p50: 3.9, p85: 4.4, p97: 4.8 },
  { month: 2, p3: 3.5, p15: 3.9, p50: 4.6, p85: 5.2, p97: 5.6 },
  // ... 共 61 条 (0-60月)
];

// 男宝体重 WHO 标准 (kg)
export const whoWeightBoy: WHOStandard[] = [
  { month: 0, p3: 2.5, p15: 2.9, p50: 3.3, p85: 3.9, p97: 4.4 },
  // ...
];

export interface WHOStandard {
  month: number;
  p3: number;
  p15: number;
  p50: number;
  p85: number;
  p97: number;
}
```

需要 6 个数据文件：体重(男/女)、身高(男/女)、头围(男/女)。

### 4.3 发育评估逻辑

```typescript
/** 根据宝宝月龄和实测值，返回所处百分位区间 */
function assessGrowth(
  ageInMonths: number,
  value: number,
  whoData: WHOStandard[]
): { percentile: string; status: 'normal' | 'low' | 'high' } {
  const std = whoData.find(d => d.month === Math.round(ageInMonths));
  if (!std) return { percentile: '无参考数据', status: 'normal' };

  if (value < std.p3)     return { percentile: '< P3', status: 'low' };
  if (value < std.p15)    return { percentile: 'P3-P15', status: 'normal' };
  if (value < std.p50)    return { percentile: 'P15-P50', status: 'normal' };
  if (value < std.p85)    return { percentile: 'P50-P85', status: 'normal' };
  if (value < std.p97)    return { percentile: 'P85-P97', status: 'normal' };
  return { percentile: '> P97', status: 'high' };
}
```

### 5.4 API 层 (api.ts 扩展)

```typescript
// 成长记录相关 API
export interface GrowthRecord {
  id: string;
  clientId: string;
  measuredAt: string;
  weight?: number;
  height?: number;
  headCircumference?: number;
  note?: string;
  recorder?: { userId: string; nickname: string };
}

export interface GrowthLatest {
  latestWeight?: { value: number; measuredAt: string; ageInDays: number };
  latestHeight?: { value: number; measuredAt: string; ageInDays: number };
  latestHead?:   { value: number; measuredAt: string; ageInDays: number };
  totalRecords: number;
}

export const fetchGrowthRecords = (babyId: string): Promise<GrowthRecord[]> =>
  apiJson(`/growth?babyId=${babyId}`);

export const fetchGrowthLatest = (babyId: string): Promise<GrowthLatest> =>
  apiJson(`/growth/latest?babyId=${babyId}`);

export const submitGrowthRecord = (data: any) =>
  apiJson('/growth', { method: 'POST', body: JSON.stringify(data) });

export const updateGrowthRecord = (clientId: string, data: any) =>
  apiJson(`/growth/by-client-id/${clientId}`, {
    method: 'PUT', body: JSON.stringify(data)
  });

export const deleteGrowthRecord = (id: string) =>
  apiJson(`/growth/${id}`, { method: 'DELETE' });
```

## 6. 页面设计

### 6.1 页面结构

成长记录页 (`/growth`) 为单页面，从上到下包含：

1. **导航栏**：返回箭头 + "成长记录" 标题 + 右上角"+"录入按钮
2. **最新指标卡片**：三列卡片（体重/身高/头围），显示最新值和周期增量
3. **维度切换 Tab**：体重/身高/头围 三选一
4. **成长曲线图**：WHO 百分位曲线 + 宝宝实际数据折线，底部发育评估条
5. **测量记录列表**：时间线样式，每条显示日期 + 三项数据 + 备注标签
6. **测量小贴士**：折叠区域，展示测量建议

### 6.2 录入表单

点击右上角"+"展开顶部表单卡片：

- 测量日期（date picker，默认今天）
- 体重（number input + "kg"单位，选填）
- 身高（number input + "cm"单位，选填）
- 头围（number input + "cm"单位，选填）
- 备注（text input，选填）
- 保存按钮

至少填写一项数据才能提交。

### 6.3 成长曲线图

使用 ECharts 绘制（体积小，移动端友好）：

- X 轴：月龄（出生, 1月, 2月, ... 当前月龄+2）
- Y 轴：体重(kg) / 身高(cm) / 头围(cm)
- 五条参考线：P3, P15, P50, P85, P97（虚线，浅绿色）
- P3-P97 区间：浅色填充（浅绿 10% 透明度）
- 宝宝数据线：实线，功能色（体重=绿色 #2e7d32，身高=蓝色 #1565c0，头围=紫色 #7b1fa2）
- 宝宝数据点：实心圆，白色边框，r=5

### 6.4 发育评估条

曲线图下方一行评估信息：

| 状态 | 颜色 | 文案 |
|------|------|------|
| 正常 | 绿色背景 | ✅ 发育正常 · 体重处于 P50-P85 百分位 |
| 偏轻 | 橙色背景 | ⚠️ 体重偏轻 · 低于 P3 百分位，建议咨询医生 |
| 偏重 | 橙色背景 | ⚠️ 体重偏重 · 高于 P97 百分位，建议咨询医生 |

## 8. 交互细节

### 8.1 首次使用

如果宝宝没有任何成长记录：
- 曲线图区域显示空状态：插画 + "还没有成长记录，点击右上角 + 开始记录吧"
- 最新指标卡片显示 "--" 占位
- 测量记录列表为空

### 8.2 数据量不足

- 仅 1 条记录：曲线图只显示一个数据点，不画连线，提示"至少需要 2 个数据点才能绘制趋势线"
- 2 条以上：正常绘制曲线

### 8.3 快捷录入

宝宝档案页 hero 区域下方，在"成长数据概览"卡片中直接显示最近一次测量的三项数据，点击跳转成长记录页。

### 8.4 离线支持

成长记录复用现有离线队列机制：
- 提交时附带 `clientId = crypto.randomUUID()`
- 网络异常时存入 `pending_growth_records` localStorage 队列
- 恢复网络后自动同步

## 11. 关键约束

- 成长记录与日常护理记录（CareRecord）是独立的两个模块，不共用事件类型枚举
- WHO 数据为静态前端数据，不需要后端接口
- 曲线图库需要引入 ECharts（推荐，体积小）
- 成长记录不参与首页的"今日统计"卡片，它是独立的低频模块
- 头围数据在 0-3 月龄阶段尤为重要（儿保必查项），UI 上不做弱化处理
