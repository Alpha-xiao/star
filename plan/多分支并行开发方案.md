## BabyStar 多分支并行开发方案

> 基于当前项目状态（main 分支有未提交改动、远程 GitHub），设计一套适合用 Trae 多窗口并行开发的 Git 工作流。

---

### 一、当前状态盘点

```
main 分支（已 push 到 GitHub）
├── 3 次 commit（初始提交 → 移除 PinMe → 升级 Vite 8）
├── 大量未提交的改动：
│   ├── 重构文件：App.vue, Home.vue, Stats.vue, api.ts 等
│   ├── 新增文件：backend/, plan/, profile.vue, profile-create.vue, baby.ts store
│   └── 删除文件：旧的 .js 文件
└── 远程: origin → https://github.com/Alpha-xiao/star.git
```

**首先需要做一件事：把当前 main 上的改动整理提交。**

---

### 二、准备工作：整理 main 分支

在开始分叉之前，先把 main 上的工作提交干净：

```bash
cd D:\workspace\star

# 1. 提交当前所有改动
git add -A
git commit -m "feat: 重构项目架构，新增后端、宝宝档案页、plan 文档"

# 2. 推到远程，作为所有分支的公共基准
git push origin main
```

这一步完成后，main 分支就是干净的、所有人都认同的基准线。

---

### 三、功能依赖图与并行分组

根据 `plan/产品功能缺失分析报告.md` 中的优先级，功能之间的依赖关系如下：

```
                    ┌─ ① 鉴权模块 (P0) ─┐
                    │                    │
         ┌──────────┤                    ├──────────┐
         │          │                    │          │
         ▼          ▼                    ▼          ▼
   ② 睡眠记录    ③ 历史趋势        ④ 家庭协作   ⑤ 记录编辑
    (独立 P0)     (独立 P0)          (依赖①)     (依赖①)
                                                    │
                                                    ▼
                                              ⑥ 数据导出
                                              (依赖①)
```

**可以并行的分组：**

| 并行组 | 功能 | 依赖 | 可与其他组并行？ |
|--------|------|------|:---:|
| A | ① 鉴权模块 | 无 | ✅ |
| B | ② 睡眠记录（纯前端 UI + 数据模型） | 无* | ✅ |
| C | ③ 历史趋势（纯前端 UI + 图表） | 无* | ✅ |
| D | ④ 家庭协作 | 依赖 ① | ❌ 等 A 完成 |
| E | ⑤ 记录编辑 | 依赖 ① | ❌ 等 A 完成 |

> *睡眠记录和历史趋势的**后端 API** 依赖鉴权，但**前端 UI 和组件**可以先在独立分支上开发，最后合并时再接入鉴权。

---

### 四、分支命名规范

```
feature/<模块名>

具体分支：
feature/auth          ← 鉴权模块
feature/sleep         ← 睡眠记录
feature/history       ← 历史数据与趋势图
feature/family        ← 家庭协作（等 auth 合并后再创建）
feature/record-edit   ← 记录编辑（等 auth 合并后再创建）
```

---

### 五、具体操作步骤

#### 第一步：创建第一批并行分支

```bash
# 确保在 main 上，且工作区干净
git checkout main
git status   # 确认 clean

# 创建三个可并行的分支
git branch feature/auth
git branch feature/sleep
git branch feature/history
```

#### 第二步：用 Trae 多窗口并行开发

**打开 3 个 Trae 窗口**，每个窗口打开同一个项目目录 `D:\workspace\star`，但切换到不同分支：

| Trae 窗口 | 执行命令 | 使用的 Prompt 文件 |
|-----------|---------|-------------------|
| 窗口 1 | `git checkout feature/auth` | `plan/鉴权模块架构设计.md` |
| 窗口 2 | `git checkout feature/sleep` | 睡眠记录的 Trae prompt（待编写） |
| 窗口 3 | `git checkout feature/history` | 历史趋势的 Trae prompt（待编写） |

每个窗口里告诉 Trae：

```
请切换到 feature/auth 分支，然后按照 plan/鉴权模块架构设计.md 中的实施步骤逐步实现。
每完成一步，先 commit 再继续下一步。
```

#### 第三步：每个分支内频繁提交

每个 Trae 窗口里，要求 Trae **每完成一个步骤就 commit 一次**：

```bash
# 在 feature/auth 分支上
git add -A
git commit -m "feat(auth): 新增 BabyMember 和 InviteCode 数据模型"

git add -A
git commit -m "feat(auth): 实现注册/登录/刷新/登出 API"

git add -A
git commit -m "feat(auth): 前端 auth store + API 层改造"

git add -A
git commit -m "feat(auth): 登录页和注册页"
```

好处：
- 出问题可以用 `git revert` 回退到具体步骤
- 合并时能看到清晰的提交历史
- 多个小 commit 比一个大 commit 更容易解决冲突

#### 第四步：合并顺序（关键！）

```
时间线:

Phase 1 (并行):
  feature/auth    ──→ 开发中...
  feature/sleep   ──→ 开发中...
  feature/history ──→ 开发中...

Phase 2 (auth 先合并):
  feature/auth ──→ ✅ merge 到 main
                   │
Phase 3 (基于新 main 创建依赖分支):
                   ├──→ feature/family (新建，基于合并后的 main)
                   └──→ feature/record-edit (新建，基于合并后的 main)

Phase 4 (sleep/history 陆续合并):
  feature/sleep   ──→ ✅ merge 到 main (可能需要 resolve conflict)
  feature/history ──→ ✅ merge 到 main

Phase 5 (family/record-edit 完成后合并):
  feature/family      ──→ ✅ merge 到 main
  feature/record-edit ──→ ✅ merge 到 main
```

合并命令：

```bash
# 合并某个 feature 分支到 main
git checkout main
git merge feature/auth --no-ff -m "feat: 用户账号与鉴权模块"
git push origin main

# 合并后，其他还未完成的分支需要 rebase 到最新 main
git checkout feature/sleep
git rebase main
# 解决冲突（如果有）后继续开发
```

#### 第五步：依赖分支的创建

当 `feature/auth` 合并到 main 后：

```bash
git checkout main
git pull origin main

# 现在 main 包含了鉴权模块，基于它创建依赖分支
git branch feature/family
git branch feature/record-edit
```

然后用新的 Trae 窗口打开这些分支继续开发。

### 六、冲突处理策略

并行开发最常见的冲突是**多个分支改了同一个文件**。

#### 高风险冲突文件（提前注意）

| 文件 | 谁会改 | 冲突概率 |
|------|--------|---------|
| `schema.prisma` | auth, sleep | **高** — 都会加新 model |
| `src/utils/api.ts` | auth, sleep, history | **高** — 都会加新 API 函数 |
| `src/router/index.ts` | auth, sleep, history | **高** — 都会加新路由 |
| `src/App.vue` | auth（路由守卫）, sleep（tabbar） | **中** |
| `src/style.css` | sleep, history | **中** — 都会加新 CSS 变量 |
| `backend/src/app.ts` | auth（注册插件）, sleep（注册路由） | **中** |

#### 降低冲突的方法

**方法 1：让 sleep 和 history 分支先不碰 auth 相关代码**

在 prompt 里明确告诉 Trae：

```
注意：当前分支不包含鉴权模块。
- 不要在 api.ts 中加 Authorization header
- 不要在路由中加 requiresAuth meta
- 不要在 App.vue 中加登录检查
这些会在合并时由鉴权分支统一处理。
```

**方法 2：合并时由你手动整合**

当 feature/sleep 合并到 main 时（此时 main 已有 auth），手动把鉴权逻辑补到 sleep 新增的 API 调用中。改动量很小，因为 auth 模块提供了统一的 `apiFetch` 函数，sleep 的新 API 函数只需要从手动 `fetch` 改为用 `apiFetch` 即可。

### 七、用 GitHub 管理（可选但推荐）

把每个 feature 分支都推到 GitHub，方便备份和 PR review：

```bash
# 推送分支到远程
git push -u origin feature/auth
git push -u origin feature/sleep
git push -u origin feature/history

# 在 GitHub 上创建 PR
gh pr create --base main --head feature/auth --title "feat: 用户账号与鉴权模块"
```

好处：
- 每个 PR 可以独立 review 和 CI 检查
- 合并时有完整的讨论记录
- 分支合并后可以安全删除
